Development release built from current `main`. Changes since 0.18.0 are **not independently
reviewed**.

- **Post-quantum strict-chat signatures.** Strict-chat unlocks, grants and "share retired"
  answers now carry an ML-DSA-65 (FIPS 204) signature next to the ECDSA one. Once both sides
  have the other's ML-DSA key, both signatures must verify, so forging an unlock needs both
  algorithms broken.
  - New strict pairings pin the keys at pairing.
  - Existing strict chats upgrade on their own at the next check after **both** the phone and
    the relay run 0.19. The phone accepts the relay's ML-DSA key only if the relay's
    already-pinned ECDSA key signed it.
- **No more TLS downgrade.** Once a server has accepted post-quantum TLS
  (`X25519MLKEM768`), this phone offers only that to it, so nobody on the network can force
  classical TLS. The phone learns this from **Test server connection**, or from its own check
  at most once a day.
  - If the server later stops offering it, the phone refuses to connect, and the connection test
    explains why.
  - **Allow classical TLS** in the test undoes it, for a proxy you changed on purpose.

## Install

Download `otp-pager-0.19.0.apk` below and install it over 0.18.0 on **both** phones. It's
signed with the same release key, so it updates in place and keeps chats, pads and pairings.
`SHA256SUMS` lists its hash.

## Server / Portainer — redeploy the relay

This release has a new relay. It adds the ML-DSA authority key, created once in the data volume
as `authority-pq-key.pem`. Keep the stack name, token, volume and network. Remove any
`RELAY_IMAGE` override, then **Pull and redeploy** with re-pull on. The pinned default is the
0.19.0 relay (`ghcr.io/masadams/otp-pager-relay:0.19.0`).

Nginx Proxy Manager: if you added `ssl_ecdh_curve X25519MLKEM768:X25519:prime256v1;`,
**keep it**. Phones that have seen it accepted now refuse classical TLS to that server. Details
are in `docs/DEPLOYMENT.md`.

## What to test

- **Relay:** after the redeploy, `authority-pq-key.pem` exists in the volume, and Test server
  connection shows ✓.
- **Strict chat:** an existing strict chat still opens after updating both phones and the relay.
  A new strict pairing works too.
- **TLS:** with the proxy line on, Test server connection says post-quantum TLS is now required.
